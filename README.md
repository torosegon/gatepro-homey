# GatePro for Homey

Control a **GatePro / TMT gate opener** from [Homey](https://homey.app) — open, close,
stop, pedestrian mode and live position — through the same **TMT Chow!** cloud the
official app uses.

The protocol was reverse‑engineered from captured traffic and the Android app; it is
documented in [`PROTOCOL.md`](PROTOCOL.md). This is an unofficial project, not affiliated
with or endorsed by TMT Automation.

## Features

- **Open · Stop · Close** as the main tile control (up / stop / down)
- Dedicated **Open**, **Close**, **Stop** and **Pedestrian** buttons
- **Pedestrian toggle** — one tap opens to the pedestrian position, the next closes it
- **Live state** — closed / opening / open / closing / stopped, from the gate’s reported position
- **Flow** action (open / close / stop / pedestrian) and a *gate state changed* trigger
- **Warm, persistent connection** — the app keeps the MQTT link open, so commands are
  near‑instant instead of paying the phone app’s per‑action cold‑start
- **Zero runtime dependencies** — a tiny built‑in MQTT client keeps the memory footprint small
- **Demo mode** — pair with the account name `demo` to explore the UI without hardware

## How it works

```
┌────────┐   HTTPS    ┌──────────────────────┐   AWS IoT MQTT   ┌───────────────┐
│  Homey │──────────▶│  Chow! cloud (auth,  │─────────────────▶│  Gate (WBT    │
│  app   │  token +   │  device list, IoT    │   commands +     │  ESP module,  │
│        │◀──────────│  certificate)         │◀─────────────────│  PS21050 panel)│
└────────┘  cert      └──────────────────────┘   live position  └───────────────┘
```

- **Authentication (HTTPS).** The app signs in to the Chow! cloud, lists the account’s
  gates and provisions an AWS IoT client certificate. Sign in with your **Chow! account
  name** (not your e‑mail) and password.
- **Control (AWS IoT MQTT).** A persistent, mutually‑authenticated MQTT connection carries
  the commands (`FULL OPEN`, `FULL CLOSE`, `STOP`, `PED OPEN`) and the gate’s reported
  position. Some controllers need an *open pulse* before they accept a close from a
  resting‑open state — the app replicates this automatically.
- **State.** The gate position is read from the AWS IoT device shadow and turned into a
  clean state with hysteresis, so the tile doesn’t flicker while the gate settles.

Everything protocol‑specific lives in `lib/` and is described in [`PROTOCOL.md`](PROTOCOL.md).

## Requirements

- A **Homey Pro** (custom apps are installed via the Homey CLI)
- A working **TMT Chow!** account with your gate already set up in the phone app
- [Node.js](https://nodejs.org/) and the [Homey CLI](https://apps.developer.homey.app/the-basics/getting-started)
  (`npm i -g homey`) for installing/developing

## Install

```bash
git clone https://github.com/torosegon/gatepro-homey.git gatepro-homey
cd gatepro-homey
npm install
homey app install     # installs onto your Homey Pro (no App Store publish needed)
```

Then add the gate in Homey (**Devices → +**), sign in with your Chow! account name and
password, and pick the gate. Re‑run `homey app install` to update later.

## Usage

The device tile shows:

| Control | Action |
| --- | --- |
| **Up / Stop / Down** | open / stop / close |
| **Open**, **Close**, **Stop** | direct commands |
| **Pedestrian** | open to the pedestrian position; tap again to close |
| **Gate state** | live status (closed / opening / open / closing / stopped) |

In Flows, use the **Send gate command** action (open / close / stop / pedestrian) and the
**Gate state changed** trigger.

## Development

```bash
npm install
homey app run          # run on your Homey with live logs
homey app validate     # validate at publish level
```

The app is authored under `.homeycompose/`; `app.json` is generated by `homey app build`.
To exercise the real cloud + MQTT path without Homey:

```bash
# CHOW_CMD = status | open | close | stop | ped   (status is safe, moves nothing)
CHOW_USER='<account name>' CHOW_PASS='<password>' CHOW_CMD=status node scripts/test-homey-path.js
```

### Project layout

```
.homeycompose/            app manifest, capabilities, flow cards
drivers/gate/             the gate driver (pairing, device, icons)

PROTOCOL.md               the reverse‑engineered protocol
```

## Notes & limitations

- **Cloud‑dependent.** The gate’s WBT module connects outbound to AWS IoT only; there is no
  local control, so the gate is unreachable during an internet outage. (A fully local setup
  would require reflashing the ESP module — a separate project.)
- **One certificate per account.** The Chow! cloud keeps a single client certificate per
  account and rotates it when the phone app signs in. If the phone re‑provisions, Homey’s
  certificate can be revoked; the app then requests a fresh one automatically. For heavy
  phone use, consider a dedicated (shared) account for Homey.

## Security

Never commit certificates, private keys, tokens, passwords, or captured traffic. The
`.gitignore` excludes `*.har`, `*.apk`, `certs/` and `env.json`. Gate commands are
authorised by the AWS IoT client certificate, not by the PIN.
